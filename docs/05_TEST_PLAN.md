## Scope, responsibilities, and environments

Verify the pipeline from source acquisition to the local CLI and Gradio demo. Review and approve this plan, [AGENTS.md](../AGENTS.md), and the [initial README](../README.md) in Phase 0 before implementation. Record technical results in this plan and approval decisions in the relevant phase record.

- **Software verification** uses Pytest for deterministic contracts, failures, boundaries, and regression checks. Use analytic arrays for tensor and metric checks and approved development images for image and model tests. Keep the ordinary test suite independent of network access and reserved test images.
- **Dataset validation** checks provenance, inventory, split integrity, and preprocessing. Combine automated checks with human review of plots, ambiguous labels, duplicate candidates, and inclusion decisions. Use the DrGFreeman release as the sole dataset.
- **Statistical model evaluation** measures predictive quality, efficiency, and generalization limits from agreed protocols. Unit checks establish that metrics are computed correctly. Model quality is assessed against approved targets at evaluation, with sample support and capture conditions reported.
- **Responsibilities and environments** · The implementer runs checks and preserves evidence. A human reviewer approves curation, phase exits, and the pre-test release gate. `L` means local VS Code, typically on CPU. `C` means Google Colab. Full epoch-based training, training-time validation, and training experiments run in Colab. Local checks include forward passes, serialization, offline validation analysis, final evaluation, and inference. `A` means automated, typically Pytest locally or an assertion-based smoke check in Colab. `M` means manual review.

## Comparison tolerances and approval gates

These are proposed starting values for specific checks. Select and record the effective value, dtype, hardware and package versions, sample IDs, justification, comparison method, and pass criterion before executing each relevant check. Compare tensors or score vectors after checking equal shapes and finite values. For predicted labels, class mappings, assignments, hashes, sample counts, and confusion counts, require exact agreement wherever identities or counts should match. An absolute tolerance below is the maximum allowed absolute elementwise difference in the stated units.

| Phase and test | Provisional tolerance or required decision | Rationale and evidence |
| --- | --- | --- |
| 1 · TP-01 | Same-environment pre/post `.keras` reload scores differ by at most `1e-6` in score units. | A float32 smoke check on a fixed small tensor allows minor numerical variation. Compare scores under the same inference settings on each runtime and record the maximum difference. |
| 1 · TP-01 portability | Colab-to-Windows CPU scores differ by at most `1e-5` per unrounded class score with exact top-class agreement. | Compare the same exported model and fixed float32 input on CPU with matched core package versions. Check the artifact hash and record the maximum absolute difference. This separate bound allows small differences across platforms. |
| 4 · TP-09 | Local and Colab deterministic tensors differ by at most `1e-5` on the normalized 0–1 scale. | Use the same development image bytes, CPU preprocessing path, and recorded contract. The bound allows small float32 rounding differences and flags meaningful decoder or transform mismatches. |
| 5–6 · TP-13 and TP-16 | Same-runtime serialization initially uses `1e-6`. Colab-to-local inference agreement initially uses `1e-5` absolute per class score using the same contract, with exact label parity. | Check unrounded scores on identical fixed development inputs. Record devices and separate serialization and cross-environment comparisons. |
| 6–7 · TP-15 and TP-17 | Independent metric implementations on identical predictions and labels agree within `1e-12` absolute in 0–1 metric units using float64 reference arithmetic. For Phase 7 recomputation on fixed development inputs, use a separately predeclared absolute macro F1 bound (proposed `1e-6`) and investigate any changed predicted labels. | Metric agreement and runtime repeatability answer different questions. Record confusion counts, sample coverage, and any changed predictions alongside the metric delta. |
| 8 · TP-19, then Phases 9–11 | Approve numerical model-quality targets, latency budgets, and final repeatability and interface parity tolerances using development results. | State each metric, value, units, direction, sample and device scope, and measurement procedure. Define interface parity as exact label match plus a limit on unrounded score difference. Capture budgets against a named CPU and declared warm-up, sample count, and summary statistic. |

If a check fails, preserve the result and investigate data identity, versions, ordering, transforms, and devices. A justified protocol change requires review and a documented rerun for every affected comparison. Choosing a tolerance after a failed check simply to pass it is prohibited. The Phase 8 gate requires approved numerical values and frozen model and data identities before the reserved test is opened.

## Execution order, regression, and phase exits

1. Run environment checks and verify Phase 1 notebook execution. Verify acquisition and inventory before EDA, and approve anomaly and grouping decisions before split freeze.
2. Audit split isolation and preprocessing before the model smoke checks. Run metric-reference checks before trusting training metrics. Reverify staging every time data moves to Colab.
3. Review baseline and experiment evidence, then pass the mandatory Phase 8 release gate before Phase 9 test access. Finish the inference and clean-environment checks in Phases 10–11.

Run focused Pytest checks after changes and rerun affected downstream checks after a change to data, transforms, model, or dependencies. A failed prerequisite blocks dependent checks. Record command, actual result, affected IDs, and next action, then preserve failed run records. Add a regression check for a defect when it can be reproduced without the reserve. Changes to frozen splits or artifacts require a reviewed new identity and comparable reruns as applicable. A phase exits when its evidence is present, failures are resolved or explicitly dispositioned within the approved requirements, and the human reviewer approves progression. After final evaluation, any test-informed changes require a reviewed evaluation plan before another held-out claim.
